Status

What works today, and what does not yet.

lvgl26 is early: version 0.0.1. This page lists what is on the main branch, with the header and the test behind each row, then what is planned, then the limits you should know before you start.

Today

On main, with tests.

Each row names its header in include/lv/, then its test in tests/.

  • Enumerators by name An LVGL enumerator is a name in quotes, in a tree, a style or set(): .align = "center". A wrong name is a compile error that lists the names. The examples name nothing of LVGL's C API, and a test keeps it so. detail/enum_names.hpp, values.hpp; enum_names.cpp, fail/enumerator_unknown_name.cpp, examples_check
  • Documentation A quick start that a test builds as a project of its own. The pages are Markdown in docs/, rendered into this site, and published for agents as llms.txt, llms-full.txt and one Markdown file a page. docs/, tools/docs.py; quick_start, quick_start_picture, docs_check
  • Editor support One CMake line, lvgl26_editor_support(), gives clangd stub headers of the public API. The editor then completes the members of lv::arc({., shows what each takes, and marks a wrong name in quotes. See Editor support. cmake/editor.cmake, tools/editor/; the editor_* tests, which need clang 19 or newer
  • Start-up without C lv::application starts LVGL and stops it when it goes out of scope; run() is the loop. lv::display draws into an lv::frame or an lv::band and tells a panel function what was drawn. A program calls no lv_init and no lv_display_*. application.hpp, display.hpp, host.hpp; application.cpp
  • Typed views lv::view<"arc"> is one pointer and never deletes. lv::owned<T> owns. lv::weak<T> empties itself when LVGL deletes the widget. view.hpp, owned.hpp; l1_views.cpp
  • Generated properties lv::props<"arc">: one member per lv_arc_set_* and lv_obj_set_* function and one per event, built by reflection from LVGL's headers. props.hpp, events.hpp; l1_views.cpp, l2_tree.cpp
  • Compile-time tree lv::column, lv::row, lv::group and 13 widgets by short name. lv::widget<"spinbox"> reaches every other widget. Ids, lv::mount, typed get<"id">. tree.hpp; l2_tree.cpp, ref/slice.png
  • Units and values px, pct, deg, ms, sec, lv::size_content. Horizontal and vertical lengths are different kinds. Integers reject bool, floating point and values that do not fit. units.hpp, values.hpp; units.cpp, values.cpp
  • Angles in the unit LVGL means Whole degrees are an lv::angle; the few values LVGL takes in tenths of a degree (an image's rotation, a style's transform rotation and skew) are lv::decidegrees. 90 * deg works for both, 22.5 * deg only where tenths are taken. Which is which is read from LVGL's doc comments at compile time, and a test checks it against the pixels. units.hpp, detail/angle_docs.hpp; angle_units.cpp
  • Styles Style properties in the tree, merged with |, stored as const lv_style_t. A design value must be a token, or lv::raw(...). style.hpp; styles.cpp, ref/styled.png
  • Images decoded on the device lv::encoded_image keeps a PNG or a baseline JPEG as its file, and LVGL's decoder draws it. For photos and large pictures. The decoders are behind the CMake options LVGL26_PNG and LVGL26_JPEG. lv/encoded_image.hpp, tests/encoded_image.cpp
  • Images from PNG files The compiler decodes an embedded PNG and stores its pixels in the display's own format: RGB565 or XRGB8888 when opaque, with alpha when see-through. No decoder and no heap on the device. A project setting limits the size. lv/image.hpp, tests/image.cpp, examples/images
  • Fonts drawn on the device lv::scaled_font owns a font that LVGL's TinyTTF draws from an embedded .ttf. A style binds to it, and every bound widget follows resize. It is behind the CMake option LVGL26_TTF. lv/scaled_font.hpp, tests/scaled_font.cpp, examples/scaled_font
  • Fonts from TrueType files The compiler reads an embedded .ttf and makes a constant font: glyphs at 4 bits per pixel and kerning in read-only memory, no heap, no converter. lv::typeface gives a typography token its font; a font without a token needs lv::raw. lv/font.hpp, tests/font.cpp, examples/fonts
  • Design tokens W3C DTCG JSON read at compile time through #embed: colors, dimensions, durations, numbers, font family and weight, easing curves, shadow, border, typography, transition and gradient. Aliases are resolved. tokens.hpp, token_types.hpp; tokens.cpp, ref/tokens_dark.png, ref/tokens_light.png
  • Themes lv::theme({...}) gives every widget of a kind its styles, for its parts and states, and a display takes it as its last argument. The styles are constants in read-only memory. lv::signal::dark and lv::signal::day are built in. lv/theme.hpp, lv/signal.hpp, tests/theme.cpp, tests/signal.cpp, examples/theme
  • State and bindings lv::state holds a measure (an mp-units quantity with an integer number), an lv::counter, a one-member struct, a bool, an enum, a color or a pointer. lv::bind ties a property to it. A state is an lv_subject_t underneath. state.hpp; state.cpp, state_plain.cpp
  • lv::computed and lv::effect A value derived from states, bound to a widget like a state, and code that runs when states change. The dependencies are fixed at compile time; nothing is registered at run time. computed.hpp; computed.cpp
  • Coroutine tasks lv::task<T> on LVGL's loop. view.next().clicked and every other event, lv::sleep, lv::first, lv::spawn. A deleted widget cancels the task. task.hpp; task.cpp
  • Animation lv::animate(widget, {.property = {from, to}}, time) for a property that takes one number: a whole number, a length, an angle or an opacity. The result says whether it ran to its end. animate.hpp; animate.cpp
  • Easing curves for animations A fourth argument of lv::animate: a name from lv::ease (LVGL\'s six animation paths and its 24 named curves), a cubicBezier design token, or an lv::bezier as in CSS. Without it the value moves at one speed. easing.hpp, animate.hpp; animate.cpp
  • Other threads lv::ui_scheduler: post() from any thread, co_await ui.schedule() in a task. Hosted only. Needs no LVGL build option. ui_scheduler.hpp; ui_scheduler.cpp, under ThreadSanitizer
  • Match lv::match with lv::is<...> and lv::otherwise. For an enum, every enumerator needs exactly one arm. match.hpp; match.cpp
  • Runtime JSON and patches lv::runtime<...>::load builds a screen from a document. apply changes properties by id. A refused document leaves nothing behind. runtime.hpp, json.hpp; runtime_ui.cpp, json.cpp
  • Agent kit The widget tree as JSON, a PNG of a widget or a screen, and an MCP server with four tools inside the host program. See Agents. dump.hpp, png.hpp, mcp.hpp; agent_kit.cpp, examples/agent/
  • Settings Project settings are a C++ specialization of lv::cfg, not a macro. config.hpp; fail/config_too_late.cpp
  • Example ports: LVGL get_started The four LVGL get_started examples, rewritten with lvgl26. Each gives the same pixels as the C original. examples/lvgl/get_started/; examples_get_started.cpp
  • Runs on a microcontroller The slice (a compile-time tree, a label bound to a state, a task) is built for an Arm Cortex-M4 with -fno-exceptions -fno-rtti and run in QEMU every night. Measured: 269 KB of code with LVGL's default configuration, 1052 bytes of LVGL's heap for the screen, 128 for the task. examples/mcu, cmake/arm, tools/arm-run.sh

Planned

Not on main yet.

None of this is available today. The order may change.

  • Example ports: more of LVGL LVGL's own widgets, layouts, styles, event, anim and scroll examples, each compared pixel for pixel with the C original. Then larger demo screens. examples/README.md
  • Importers Offline host tools that convert existing UI descriptions to the lvgl26 JSON schema.
  • import lv; The library as a C++ module, next to the headers.
  • Linter, profiler, debugger Tools that a person or an agent can drive, exposed through the agent kit.
  • More documentation, for people and agents The reference, generated by reflection and as data; guides and explanations; pages for readers who know Qt, Slint or TouchGFX; an error catalogue; skills for agents that write C++.
  • Components Components that hold state and a view, used several times in a tree.
  • Design showcase One design system, Signal, for a family of eight devices: mood boards and the system are done (see Design); the device screens and their lvgl26 firmware follow. design/signal
  • Design tool adapters Adapters that write tokens.json from a design tool, so that tokens are never copied by hand.
Limits

Known limits.

Read these before you plan a product on it.

Compiler and platform

  • GCC 16 or newer only, with -std=c++26 -freflection. Reflection is a hard dependency. Clang cannot compile the code yet, so clang-tidy cannot analyze it either.
  • CMake 3.30 or newer and Ninja.
  • Headers only. There is no import lv; yet.
  • One microcontroller is proven, in an emulator. The slice runs on a Cortex-M4 in QEMU. No real board, no display driver and no other processor family has been tried, and there is no size budget yet.
  • ThreadSanitizer runs on Linux only.
  • The v10 line is a pinned commit. LVGL v10 has no release yet and keeps moving.
  • Early. Version 0.0.1. Names and signatures can still change.

Language and library

  • Designated initializers must be in alphabetical order (.id, .range, .value). This is a C++ rule for members in declaration order.
  • A misspelled or misordered member is reported as could not convert '{...}' to props<"arc">. GCC does not name the member in that case.
  • A quantity in a state needs an integer number for now.
  • mp-units is yours to add. lvgl26 has no unit system for application values and does not include one.
  • Animations take one number per property, and one property for each call.
  • Hosted parts: lv::ui_scheduler, the PNG writer and the MCP server allocate or use the C library's files. They are not for a freestanding build.
  • Runtime documents: text values are at most 127 characters and are not unescaped. At most 32 nodes can have an id. Handlers, bindings and pointers cannot come from a document.
  • The MCP server blocks while it waits for a line, and speaks over stdin and stdout only.
